# Build workflow: one builder, many agents

How Mohamed builds FundEli5 with coding agents from Wed 28 Oct to the event. Agreed on 2026-10-28, superseding [What prompts build the skeleton app in 60 minutes?](https://github.com/smnajid/fund-gate/issues/29). Dates and checkpoints come from [team-plan.md](team-plan.md); modules come from [architecture.md](architecture.md#modules).

## The rules

1. **`specs/` is the definition of done.** A ticket is done when its module's Cucumber tag passes and `@answer-key` still passes.
2. **Agents never edit `specs/` or [hypotheses.md](hypotheses.md).** An agent that thinks a scenario is wrong stops and says why, and Mohamed decides. An agent can otherwise make a scenario pass by rewriting it. `/pre-merge` checks that `git diff main -- specs/ docs/playbook/hypotheses.md` is empty, unless the ticket says the change is the point.
3. **The specs are the oracle, not the whole input.** Each ticket also points to the glossary, its ADRs, its row in `architecture.md`, its contract or schema, and its rows in `hypotheses.md`.
4. **A missing business answer becomes a hypothesis, not a guess in code.** When an agent needs an answer that isn't in the register, it stops. Mohamed adds the row and its `@assumed` scenario, then restarts the ticket.
5. **No spec framework on top.** OpenSpec, Spec Kit and similar tools would add a second source of truth next to Gherkin that already runs. The equivalents are already here: ADRs give the why, GitHub issues are the units of change, and `/to-tickets`, `/tdd` and `/implement` are the loop.

## Order: one at a time for the spine, then parallel

The limit isn't how many agents run. It's how many diffs Mohamed can review in a day. Parallel work starts only once the seams exist, so two agents never invent the same types.

## How much an agent does alone

| Modules | Mode | Gate before Mohamed reads the diff |
|---|---|---|
| Rule Engine, Scale Mapping, reverse lookup, what-if | HITL: `/tdd`, Mohamed picks each next example | module tag + `@answer-key` green; `engine-purity-reviewer` |
| Privacy Gate, Request Parser, Reply Drafter, LLM egress client | HITL | module tag green; `privacy-gate-auditor` |
| Share Class catalog, Check Record, Validation UI, Rule Card pipeline port, explanation templates, form checklist, Angular screens | AFK: `/implement` in a worktree until the gate passes | module tag green; `java-reviewer` or `typescript-reviewer` reports nothing; `privacy-gate-auditor` if a client field is touched |

An AFK agent that hits a stop condition (below) stops and reports. It never works around the condition.

## The build ticket

`/to-tickets` publishes one GitHub issue per row above, labelled `ready-for-agent` (AFK) or `ready-for-human` (HITL), with native blocking edges that follow the spine and the waves. Every body follows this template, so an agent starting cold has everything it needs:

```markdown
## Goal
<one sentence in GLOSSARY.md terms: what the module does in Anna's flow>

## Done when
- `./mvnw test -Dtest=SpecificationSuite -Dcucumber.filter.tags="<module tags>"` passes, with no undefined step
- `@answer-key` still passes
- <gate agents> report nothing

## Read first
- GLOSSARY.md; ADRs <numbers>
- architecture.md, row "<module>"; contract or schema: <path>
- hypotheses.md rows: <tickets>, or "none"

## Seam
May change: <packages / folders>. Calls only: <ports or modules>.

## Must not
- edit specs/, docs/playbook/hypotheses.md, generated client code, or another module's package
- call the LLM except through the egress client (ADR 0004)

## Stop and ask when
- a scenario looks wrong or contradicts an ADR
- a business answer is needed that hypotheses.md does not give
- a port or schema signature must change
```

## Day to day

| When | Do |
|---|---|
| Start a ticket | `claude --worktree <module>`, then `/tdd <issue>` (HITL) or `/implement <issue>` (AFK) |
| Before merging | `/pre-merge` once it exists ([Build the /pre-merge skill](https://github.com/smnajid/fund-gate/issues/28)). Until then: the module tags, `@answer-key`, the gate agents, and the empty `specs/` diff |
| API changed | Regenerate the Angular client and commit both sides together |
| A hypothesis changes | Follow [hypotheses.md](hypotheses.md#how-to-change-a-hypothesis); the failing scenarios become the follow-up ticket |
| End of day | At most 3 branches open; merge or park the rest |
